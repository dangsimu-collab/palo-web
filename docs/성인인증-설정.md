# 성인 게시판 본인확인 — 설정 순서

코드는 이미 다 들어가 있습니다. **아래 순서대로 하면 켜집니다.**
현재 상태: `ADULT_BOARD_ENABLED=false` 라서 성인 게시판 자체가 보이지 않습니다(안전).

---

## 1단계. 사업자등록 (본인이 직접)

본인확인 서비스는 **사업자만 계약할 수 있습니다.**

- 국세청 홈택스 또는 정부24에서 **개인사업자** 등록 (수수료 없음)
- 업종: 정보통신업 / 포털 및 기타 인터넷 정보매개 서비스업 (`63120`) 정도가 무난
- 통신판매업 신고는 **불필요** (본인인증만 쓰고 결제를 받지 않는 경우)

> 사업자등록을 하면 종합소득세 신고 의무가 생깁니다. 수익이 없어도 무실적 신고는 해야 합니다.

---

## 2단계. 포트원 가입 + KG이니시스 통합 본인인증 신청

1. https://admin.portone.io 회원가입
2. **결제 연동 → 채널 관리 → 채널 추가**
3. **KG이니시스 · 통합 본인인증** 선택 후 신청
4. 사업자등록증 제출 → 심사 (보통 며칠)

**요금**: 가입비 0원 · 연관리비 0원 · **성공 건당 40원**(VAT 별도)
**지원 수단**: 네이버 · PASS · 토스 · 카카오 · 페이코 · 금융인증서 · 신한 · KB모바일 · 삼성패스

## 2.5단계. DB에 2차 보완 SQL 실행

`docs/sql/adult-verification.sql` 을 이미 실행하셨다면, **`docs/sql/adult-verification-2.sql` 도 실행**하세요.

- CI 대신 **DI**를 쓰도록 컬럼 이름을 바꿉니다(`adult_ci_hash` → `adult_di_hash`)
- 한 번 쓴 본인확인 번호를 재사용하지 못하게 막습니다

> **CI는 신청하지 마세요.** KCP의 CI·DI 제공신청서에서 **DI만 체크**하면 됩니다.
> CI는 모든 기관 공통 식별자라 연계정보 안전조치 실태점검 대상이 될 수 있는데,
> 우리 용도(한 사람당 한 계정)는 사이트별 값인 DI로 충분합니다.

## 3단계. 키 3개 넣기

### (a) 프론트 — `public/palo.js` 상단 성인인증 섹션

```js
var PORTONE_STORE_ID="store-xxxxxxxx";      // 관리자 콘솔 → 결제 연동
var PORTONE_CHANNEL_KEY="channel-key-xxxx";  // 채널 관리 탭
```

두 값이 채워지면 `ADULT_VERIFY_READY`가 자동으로 `true`가 됩니다.
(이 두 값은 브라우저에 노출돼도 되는 공개 값입니다.)

### (b) 서버 — Vercel 환경변수 (Settings → Environment Variables)

| 이름 | 값 |
|---|---|
| `PORTONE_API_SECRET` | 관리자 콘솔 → **API Secret** (⚠️ 절대 공개 금지) |
| `ADULT_ID_SALT` | 아무도 모르는 긴 무작위 문자열 |

`ADULT_ID_SALT`는 아래로 만드세요:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> ⚠️ **`ADULT_ID_SALT`는 한 번 정하면 절대 바꾸지 마세요.** 바꾸면 기존 인증자들의
> 중복 확인 값이 전부 달라져서, 한 사람이 계정을 여러 개 인증할 수 있게 됩니다.
>
> 예전 이름 `ADULT_CI_SALT`로 이미 넣어 두셨다면 그대로 둬도 동작합니다(코드가 둘 다 받습니다).
> 이름만 바꾸실 거면 **값은 그대로** 옮기세요.

환경변수를 넣은 뒤 **Redeploy** 해야 반영됩니다.

## 동작 확인 체크리스트

켠 뒤 이것들을 직접 확인하세요:

- [ ] 로그아웃 상태에서 성인 게시판 클릭 → 로그인 창
- [ ] 로그인·미인증 상태에서 클릭 → 인증 안내 창
- [ ] 인증 완료 → 게시판 진입 가능
- [ ] 다른 계정으로 같은 명의 인증 시도 → "이미 다른 계정에서 인증됨" 거부
- [ ] 미인증 계정에서 브라우저 콘솔로 확인 (아래가 **거부**되어야 정상)

```js
await supabase.from('profiles').update({adult_verified:true}).eq('id', AUTH.user.id)
// → "성인 인증 정보는 직접 변경할 수 없습니다" 오류가 나야 함

await supabase.from('posts').select('*').eq('board','adult')
// → 0건이어야 함
```

## 구조 요약

```
브라우저 ──(1) 인증창 요청──> 포트원 SDK ──> PASS/토스/카카오…
    │                                            │
    │<──────────(2) identityVerificationId ───────┘
    │
    └─(3) POST /api/auth/adult-verify ─> 서버
                                          │
                                          ├─(4) 포트원 API로 결과 재조회 ★
                                          ├─(5) 연 나이 19세 이상 판정
                                          ├─(6) CI 해시로 중복 계정 확인
                                          └─(7) profiles.adult_verified = true
```

**★ (4)가 핵심입니다.** 브라우저가 보낸 값을 믿지 않고 서버가 포트원에 직접 물어봅니다.
이게 없으면 콘솔에서 가짜 id를 보내는 것만으로 뚫립니다.

### 저장하는 것 / 안 하는 것

| 저장함 | 저장 안 함 |
|---|---|
| `adult_verified` (예/아니오) | 이름 |
| `adult_verified_at` (일시) | 생년월일 |
| `adult_di_hash` (해시값) | 휴대폰번호 |
| | 원본 CI |

생년월일은 나이 계산에만 쓰고 즉시 버립니다. 해시값은 유출돼도 개인을 특정할 수 없습니다.
