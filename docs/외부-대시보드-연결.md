# 외부 대시보드로 데이터 보기

가입자(이메일 포함) · 글 · 댓글 · 커미션 · 광고 성과를 사이트 밖에서 표와 그래프로 보는 방법입니다.

---

## 0. 지금 상태

관리자 페이지(`/admin`)는 **브라우저에서 직접 Supabase를 읽는 방식**이라 `auth.users`에 있는
**이메일 · 로그인 수단 · 마지막 접속은 원래 못 읽습니다.** 그래서 지금까지 이메일이 안 보였습니다.

외부 도구는 **DB에 직접 붙기** 때문에 그 제약이 없습니다. 대신 아무 계정이나 주면 위험하므로
읽기 전용 계정과 정리된 뷰를 먼저 만듭니다.

---

## 1단계. SQL 실행 (필수, 5분)

`docs/sql/bi-readonly.sql` 을 Supabase → **SQL Editor** 에 붙여넣고 실행합니다.

> ⚠️ **붙여넣기 전에** 파일 아래쪽 `'비밀번호를_여기에_직접_적으세요'` 를 직접 정한 값으로 바꾸세요.
> 20자 이상, 다른 곳에 쓰지 않는 새 비밀번호로. **그 값을 파일에 저장하지 마세요** — 이 저장소는 공개입니다.

무엇이 만들어지나요:

| 뷰 | 내용 |
|---|---|
| `bi.회원` | 닉네임 · **이메일** · 로그인 수단 · 가입일 · 마지막 접속 · 등급 · 점수 · 글/댓글/커미션 수 |
| `bi.글` | 게시판 · 제목 · 작성자 · 조회수 · 좋아요 · 댓글 수 · 블라인드 여부 |
| `bi.댓글` | 어느 글의 댓글인지 · 작성자 · 내용 · 작성일시 |
| `bi.커미션` | 작가 · 상태 · 가격 · 태그 · 조회수 · 신청 수 · 수락 수 |
| `bi.커미션신청` | 커미션 · 작가 · 신청자 · 상태 · 신청/처리 시각 |
| `bi.캠페인` · `bi.광고성과일별` | 캠페인별 방문자 · 가입 · 행동, 가입 1명당 비용 |
| `bi.일별요약` | 날짜별 가입 · 글 · 댓글 · 좋아요 · 커미션 (활동 없는 날도 0으로) |
| `bi.삭제된댓글` · `bi.삭제된커미션` | 관리자가 지운 것들의 보관본 |

동시에 `bi_reader` 계정이 만들어집니다. **읽기만** 되고, **위 뷰만** 볼 수 있고,
동시 접속 5개 · 쿼리 30초 제한이 걸려 있습니다.

**왜 원본 테이블을 그냥 안 여는가**: 뷰에 넣은 것만 보이기 때문입니다. 비밀번호 해시,
본인확인 DI 해시, 커미션 신청서 답변 원문 같은 건 뷰에 아예 넣지 않았습니다.
나중에 테이블 구조가 바뀌어도 뷰만 고치면 대시보드는 그대로 씁니다.

## 2단계. 접속 정보 확인

Supabase → **Project Settings → Database → Connection string** 에서 **Session pooler** 를 고릅니다.

| 칸 | 값 |
|---|---|
| Host | 대시보드에 나온 `aws-0-...pooler.supabase.com` 를 그대로 복사 |
| Port | **5432** (Session pooler) |
| Database | `postgres` |
| User | **`bi_reader.qabbdgfottbnapmyjudy`** ← 계정 이름 뒤에 점 + 프로젝트 ID |
| Password | 1단계에서 직접 정한 값 |
| SSL | 켜기 (필수) |

> ⚠️ **포트 6543(Transaction pooler)은 쓰지 마세요.** 대시보드 도구가 쓰는 준비된 쿼리(prepared statement)를
> 지원하지 않아 연결이 되다 말다 합니다. 5432(Session)가 맞습니다.
>
> ⚠️ 사용자 이름에 `.qabbdgfottbnapmyjudy` 를 안 붙이면 pooler가 어느 프로젝트인지 몰라 인증에 실패합니다.

## 3단계. 도구 고르기

| | Looker Studio | Metabase (직접 설치) | Grafana Cloud |
|---|---|---|---|
| 비용 | **무료** | 무료(서버비 월 5천원~) | 무료 요금제 있음 |
| 설치 | 없음, 웹에서 바로 | 서버에 직접 설치 필요 | 없음 |
| 한국어 | 됨 | 됨 | 영어 |
| 표 훑어보기(댓글·가입자) | 보통 | **가장 좋음** | 약함 |
| 그래프 | 좋음 | 좋음 | **가장 좋음** |
| 공유 | 구글 계정으로 링크 공유 | 계정 직접 관리 | 팀 초대 |

**추천: Looker Studio 로 시작하세요.** 설치도 비용도 없고 한국어로 쓸 수 있습니다.
쓰다가 "댓글을 검색해서 훑어보는" 쪽이 답답하면 그때 Metabase로 옮기면 됩니다 —
**1단계에서 만든 뷰는 어느 도구든 그대로 쓸 수 있어서 옮겨도 다시 만들 게 없습니다.**

### Looker Studio 연결

1. https://lookerstudio.google.com 접속 → **만들기 → 데이터 소스**
2. 커넥터 목록에서 **PostgreSQL** 선택
3. 2단계의 값을 입력하고 **SSL 사용** 체크 → **인증**
4. `커스텀 쿼리` 대신 **테이블 목록**에서 `bi` 스키마의 뷰를 고르면 됩니다
5. 보고서를 만들고 표·그래프를 올립니다

### Metabase 로 갈 경우

1. 서버(Railway, Fly.io, 또는 집 PC의 Docker)에 Metabase를 올립니다
2. **관리자 → 데이터베이스 추가 → PostgreSQL** 에 2단계 값을 입력
3. `bi` 스키마만 동기화하도록 **Schemas** 칸에 `bi` 를 적습니다

## 4단계. 보안 수칙 (꼭 지켜주세요)

- **`postgres` 계정을 대시보드 도구에 절대 입력하지 마세요.** 그 계정은 데이터를 지울 수 있습니다.
  도구가 털리면 사이트가 통째로 털립니다. 반드시 `bi_reader` 만 씁니다.
- **`bi.회원` 에는 가입자 이메일이 들어 있습니다.** 보고서 공유 링크를 "링크가 있는 모든 사용자"로
  열지 마세요. 본인 계정만, 필요하면 지정한 사람에게만 공유하세요.
- 비밀번호는 **대시보드 도구에만** 넣고, 파일·메모·채팅 어디에도 남기지 마세요.
- 더 이상 안 쓰면 계정을 지우세요:
  ```sql
  drop role bi_reader;
  ```

### 개인정보처리방침은 고칠 필요가 있나요? — **고르는 도구에 따라 다릅니다**

핵심은 **가입자 이메일이 남의 회사 서버에 남느냐**입니다.

| 경우 | 이메일이 외부에 남나 | 처리방침 |
|---|---|---|
| Metabase를 **직접 설치**해서 씀 | 남지 않음(내 서버) | 고칠 것 없음 |
| Looker Studio·Grafana Cloud 등 **클라우드 도구** | **남습니다** — 조회 결과가 그 회사 서버에 캐시됨 | 처리위탁 고지 필요 |
| 클라우드 도구를 쓰되 **이메일을 뷰에서 뺌** | 남지 않음(닉네임·통계만) | 고칠 것 없음 |

클라우드 도구는 "볼 때마다 우리 DB에 물어보는" 구조가 맞지만, **속도를 위해 조회 결과를 자기 서버에
일정 시간 저장(캐시)합니다.** 그 결과에 이메일이 들어 있으면 이메일이 그 회사에 보관되는 것이고,
개인정보보호법상 처리위탁으로 볼 여지가 생깁니다(위탁하면 처리방침에 수탁자와 위탁 업무를 공개해야 합니다).

**가장 간단한 해결**: 클라우드 도구를 쓸 거라면 뷰에서 이메일만 빼세요. 그러면 고민할 게 없어집니다.

```sql
-- 이메일 없이 다시 만들기 (닉네임·가입일·등급·활동량은 그대로)
drop view if exists bi.회원 cascade;
create or replace view bi.회원 as
select
  u.id as "회원번호", p.nickname as "닉네임",
  coalesce(u.raw_app_meta_data ->> 'provider','email') as "로그인수단",
  u.created_at as "가입일시", u.last_sign_in_at as "마지막접속",
  p.level as "등급", p.score as "점수", p.is_admin as "관리자", p.is_banned as "차단됨",
  (select count(*) from public.posts    x where x.author_id = u.id) as "글수",
  (select count(*) from public.comments x where x.author_id = u.id) as "댓글수"
from auth.users u
left join public.profiles p on p.id = u.id;
grant select on bi.회원 to bi_reader;
```

이메일이 꼭 필요한 순간(공지 메일 발송 등)에는 Supabase SQL Editor에서 그때만 조회하면 됩니다.

⚠️ 어느 쪽이든 **구글 시트로 내보내기·예약 메일 발송처럼 데이터를 실제로 복사해 두는 기능**은
켜지 마세요. 그건 명확히 외부 보관입니다.

> 법률 자문이 아닙니다. 판단이 애매하면 이메일을 빼는 쪽(가장 안전)을 택하세요.

## 문제 해결

| 증상 | 원인 |
|---|---|
| 인증 실패 | 사용자 이름에 `.qabbdgfottbnapmyjudy` 를 안 붙였거나 비밀번호가 다름 |
| 연결이 되다 말다 함 | 포트 6543을 씀 → **5432(Session pooler)** 로 |
| 뷰가 하나도 안 보임 | 도구에서 `public` 스키마만 보고 있음 → `bi` 스키마를 지정 |
| 표가 전부 비어 있음 | SQL을 실행한 계정이 아니라 `bi_reader` 로 붙었는지 확인. 권한 구문(`grant`)까지 다 실행됐는지도 |
| 한글 컬럼명이 깨짐 | 도구에서 SQL을 직접 쓸 때는 큰따옴표로 감싸야 합니다: `select "닉네임" from bi.회원` |
| 쿼리가 30초에서 끊김 | 일부러 건 제한입니다. 필요하면 `alter role bi_reader set statement_timeout = '60s';` |
