# Cloudflare R2 설정 순서

코드는 다 들어가 있습니다. 아래 순서대로 하면 켜집니다.
**환경변수 5개가 채워지기 전까지는 업로드가 "저장소 설정이 준비되지 않았어요"로 막힙니다.**

---

## 1단계. 버킷 만들기

1. https://dash.cloudflare.com → 왼쪽 메뉴 **R2**
2. 처음이면 결제 수단 등록 (무료 한도 안에서는 청구되지 않음)
3. **Create bucket** → 이름 `commi-images` → Location: **Asia-Pacific (APAC)**

> 무료 한도: 저장 10GB · Class A 100만 · Class B 1,000만 요청 / **이그레스 무제한 무료**

---

## 2단계. 공개 주소 연결

버킷 → **Settings** → **Public access**

**권장: 커스텀 도메인**

- **Connect Domain** → `img.commi.kr` 입력
- commi.kr이 이미 Cloudflare DNS를 쓰면 자동 설정되고, 아니면 안내되는 CNAME을 등록
- 이러면 Cloudflare CDN 캐시까지 붙습니다

**간단히 하려면: r2.dev**

- **Allow Access** 를 켜면 `https://pub-xxxx.r2.dev` 주소가 생김
- ⚠️ 속도 제한이 있고 운영용으로는 권장되지 않음. 테스트용으로만

여기서 정한 주소가 아래 `R2_PUBLIC_BASE` 입니다.

---

## 3단계. CORS 허용 (필수)

브라우저가 R2로 **직접** 파일을 올리기 때문에 이게 없으면 업로드가 전부 실패합니다.

버킷 → **Settings** → **CORS Policy** → **Add CORS policy**

```json
[
  {
    "AllowedOrigins": [
      "https://commi.kr",
      "https://www.commi.kr",
      "http://localhost:3000"
    ],
    "AllowedMethods": ["PUT", "GET"],
    "AllowedHeaders": ["content-type"],
    "MaxAgeSeconds": 3600
  }
]
```

---

## 4단계. API 토큰 발급

R2 첫 화면 오른쪽 **{ } API** → **Manage API tokens** → **Create API token**

- 이름: `commi-upload`
- 권한: **Object Read & Write**
- 대상: 위에서 만든 버킷만 지정 (전체 계정 권한을 주지 말 것)

발급되면 세 가지가 나옵니다. **이 화면을 벗어나면 다시 볼 수 없으니** 바로 복사하세요.

- **Access Key ID**
- **Secret Access Key**
- **Account ID** (R2 첫 화면 오른쪽에도 있음)

---

## 5단계. 환경변수 넣기

Vercel → 프로젝트 → **Settings → Environment Variables**

| 이름 | 값 | 예시 |
|---|---|---|
| `R2_ACCOUNT_ID` | Cloudflare 계정 ID | `a1b2c3...` |
| `R2_ACCESS_KEY_ID` | 토큰의 Access Key ID | |
| `R2_SECRET_ACCESS_KEY` | 토큰의 Secret (⚠️ 공개 금지) | |
| `R2_BUCKET` | 버킷 이름 | `commi-images` |
| `R2_PUBLIC_BASE` | 2단계에서 정한 공개 주소 | `https://img.commi.kr` |

`R2_PUBLIC_BASE`는 **끝에 슬래시를 붙이지 마세요.**

넣은 뒤 **Redeploy** 해야 반영됩니다.

로컬에서도 테스트하려면 같은 값을 `.env.local` 에 넣으세요.

---

## 6단계. 기존 이미지 옮기기

새 업로드는 바로 R2로 갑니다. **예전에 올라간 이미지는 그대로 Supabase에 남아 있고 계속 잘 보입니다** — 급하지 않지만, 정리하려면:

```bash
node scripts/migrate-storage-to-r2.mjs
```

먼저 이렇게 실행하면 **무엇이 바뀌는지 보여주기만** 합니다. 확인한 뒤:

```bash
node scripts/migrate-storage-to-r2.mjs --apply
```

- 원본은 **지우지 않습니다.** 문제가 생기면 DB 주소만 되돌리면 원상복구됩니다
- 여러 번 실행해도 안전합니다 (이미 옮긴 건 건너뜀)
- 글 본문 HTML 안에 박힌 `<img src>` 도 같이 바꿉니다

잘 돌아가는 걸 며칠 확인한 뒤에 Supabase Storage의 옛 파일을 지우세요.

---

## 동작 확인

1. 글쓰기 → 이미지 첨부 → 올라가는지
2. 올라간 이미지 주소가 `R2_PUBLIC_BASE` 로 시작하는지 (우클릭 → 이미지 주소 복사)
3. 프로필 사진 · 커버 변경
4. 커미션 등록 시 이미지
5. **GIF** 업로드 → 움직이는지 (압축을 건너뛰므로 원본 그대로 올라감)

업로드가 실패하면 브라우저 콘솔의 오류를 보세요:

| 증상 | 원인 |
|---|---|
| **일부 기기·통신사에서만 이미지가 안 보임** | **DNS 전파 지연** — 아래 참고 |
| `CORS` 오류 | 3단계 CORS 정책 누락 |
| `403` | 서명 불일치 — `R2_ACCESS_KEY_ID`/`SECRET` 확인 |
| "저장소 설정이 준비되지 않았어요" | 환경변수 5개 중 빠진 것이 있음 |
| 업로드는 되는데 이미지가 안 보임 | 2단계 공개 접근이 꺼져 있거나 `R2_PUBLIC_BASE` 오타 |

## 구조

```
브라우저 ──(1) 어디에 올릴지 요청──> /api/storage/upload-url
                                        │ 로그인 확인
                                        │ 형식·용량 확인
                                        │ 저장 경로를 **서버가** 결정
                                        ↓
         <──(2) 2분짜리 서명 URL ────────┘
   │
   └─(3) R2에 직접 PUT ──────────> Cloudflare R2
                                        │
         <──(4) 공개 주소로 표시 ────────┘
```

**(3)이 핵심입니다.** 파일이 우리 서버를 거치지 않아서 Vercel의 요청 본문 제한(4.5MB)에
걸리지 않습니다. 40MB짜리 GIF도 올라가는 이유예요.

**저장 경로를 서버가 정하는 것**도 중요합니다. 클라이언트가 경로를 고르게 하면
남의 파일 경로를 지정해 덮어쓸 수 있습니다.

삭제(`/api/storage/delete`)는 키가 `<폴더>/<본인 uid>/…` 형태인 것만 지웁니다.
Supabase Storage의 버킷 정책이 해주던 일을 이제 이 라우트가 대신합니다.

## ⚠️ 성인 게시판을 켜기 전에

R2 버킷을 공개로 두면 **주소를 아는 사람은 누구나** 이미지를 볼 수 있습니다.
Supabase Storage도 마찬가지였지만, 성인 게시판에서는 이게 **연령 확인 우회**가 됩니다.

성인 게시판 이미지는 별도 처리가 필요합니다:

- 비공개 버킷에 넣고 조회 시에도 서명 URL 발급, 또는
- 이미지 요청을 서버 라우트로 받아 인증 확인 후 전달

성인 게시판 오픈 전 체크리스트에 포함할 것.

## 이미지가 "어떤 기기에선 보이고 어떤 기기에선 안 보일" 때

DNS를 Cloudflare로 옮긴 직후에 겪는 일입니다. **코드 문제가 아닙니다.**

`img.commi.kr`은 새로 만든 이름이라, 옛 네임서버(가비아)를 캐시하고 있는 리졸버는
가비아에 물어보고 "그런 도메인 없음"을 받습니다. 가비아에는 `img` 레코드가 없으니까요.

2026-08-07 실측 예: Google·Cloudflare·SK브로드밴드·LG U+는 정상, **KT(168.126.63.1)만 실패**.
Edge는 보안 DNS(DoH)로 Cloudflare에 직접 물어봐서 되고, Chrome·휴대폰은 통신사 DNS를 써서 안 됐다.

### 확인 방법

```bash
nslookup img.commi.kr 8.8.8.8          # 정상이어야 함
nslookup img.commi.kr 168.126.63.1     # 여기서 실패하면 전파 대기 중
nslookup -type=NS commi.kr 168.126.63.1  # 가비아가 나오면 아직 옛 정보를 캐시 중
```

남은 시간은 캐시 TTL로 확인:

```bash
nslookup -debug -type=NS commi.kr 168.126.63.1   # ttl 값이 남은 초
```

### 대처

1. **기다리기(권장)** — NS 캐시 TTL이 지나면 저절로 풀린다(실측 최대 10시간)
2. **급하면**: 가비아 DNS에 `img` A 레코드를 임시로 추가한다(가비아 존이 아직 살아 있어 응답함)
   - `img` A `104.21.25.43` / `img` A `172.67.222.173` (Cloudflare 엣지, TTL 600)
   - 전파가 끝나면 아무도 가비아에 묻지 않으므로 나중에 삭제
3. 테스트만 할 거면 기기 DNS를 `1.1.1.1`로 바꾸면 즉시 보인다

⚠️ 이 기간에 **새로 올린 이미지는 일부 이용자에게 안 보입니다.** 급한 업로드는 미루는 게 좋습니다.
